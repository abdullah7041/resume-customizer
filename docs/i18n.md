# Watheq i18n Workflow

## Overview

Watheq is bilingual (EN/AR). English is the source of truth. Arabic translations are managed through feature-based namespace JSON files under `src/locales/ar/`.

## Where Translations Live

```
src/locales/
  utils.ts                # deepMerge helper with collision detection
  en/
    index.ts              # aggregates all EN namespaces
    common.json
    credits.json
    landing/
      hero.json
      demo.json
      productWalkthrough.json
      productStory.json
      features.json
      content.json        # remaining landing keys (stats, industries, comparison, etc.)
    sections/
      resume.json
      match.json
      optimize.json
      keywords.json
      templates.json
      interview.json
      bulk.json
      bulkAnalysis.json
      coverLetter.json
      optimizationResults.json
    ...
  ar/
    index.ts              # aggregates all AR namespaces (same structure as en/)
    ...
```

## How to Add a New Key

1. Add the English key first in the appropriate `src/locales/en/` namespace file.
2. Run `npm run i18n:missing` to generate the local `i18n-missing-ar.json` report.
3. Add the Arabic translation to the corresponding `src/locales/ar/` file.
4. Run `npm run i18n:validate` to confirm parity.

## How to Add a New Namespace

1. Create `src/locales/en/<namespace>.json` with the new key tree.
2. Create `src/locales/ar/<namespace>.json` with the Arabic translations (or leave empty for now).
3. Import both in `src/locales/en/index.ts` and `src/locales/ar/index.ts`.
4. Run `npm run i18n:validate`.

## How to Validate Translations

```bash
npm run i18n:validate
```

Checks:
- Every EN key exists in AR.
- Every AR key exists in EN.
- No empty string values.
- i18next interpolation variables (`{{var}}`) match between EN and AR.
- No key collisions across namespace files.

Exits with code `1` if any issue is found.

## How to Generate Missing Arabic Translation Prompts

```bash
npm run i18n:missing           # generates local i18n-missing-ar.json
npm run i18n:translation-prompt # generates local i18n-translation-prompt-ar.md
```

These generated files are ignored by git. The prompt file is safe to share with a translation service or AI. It includes:
- A glossary of product terms.
- ICU/interpolation preservation rules.
- The exact missing key list.

## Important Rules

- Core UI should use static reviewed translations, not runtime AI translation.
- Do not insert `[AR_MISSING]` placeholders into committed AR files.
- Leave missing keys absent so validation catches them.
- The app uses `fallbackLng: 'en'` in `src/lib/i18n.ts`, so missing Arabic keys gracefully fall back to English at runtime.
- Do not add new paid API dependencies for translation unless explicitly approved.

## CI Integration

The validation script is CLI-safe and can be added to CI:

```bash
npm run i18n:validate
```

If it exits non-zero, the build should fail.
