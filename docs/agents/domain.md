# Domain docs

This is a single-context repository.

Before exploring code, read `CONTEXT.md` and any relevant ADRs under
`docs/adr/` when they exist. Missing domain documents are not an error;
continue silently. The domain-modeling workflow creates them lazily
when terminology or architectural decisions are resolved.

Use terminology defined in `CONTEXT.md` consistently in code, tests,
issues, and plans. Explicitly surface proposed work that contradicts an
existing ADR.
