# Watheq Frontend UX

Use this skill for Watheq frontend/product experience work. Keep the process focused on product proof, Saudi-market trust, bilingual usability, and scoped frontend implementation.

## Start With Questions

Always start with AskUserQuestions for ambiguous UX/product tasks.

- Ask exactly 1 to 3 focused questions.
- Do not ask questions for trivial copy/color fixes.

## Pre-Implementation Check

Before implementing, identify:

- Target user outcome
- Primary CTA
- Product proof to show
- Desktop layout
- Mobile layout
- Animation intensity
- Accessibility and reduced-motion considerations
- Arabic/RTL impact

## Landing Pages

For landing-page work:

- Avoid generic SaaS cards.
- Avoid excessive empty cards.
- Avoid decoration without product proof.
- Prioritize Watheq-specific differentiators:
  - Vision 2030 analysis
  - Ask-before-optimization clarification questions
  - ATS before/after improvement
  - Interview questions generated from resume/job
  - Arabic + English support

## Scroll Animation

For scroll animation:

- Prefer CSS scroll-driven animation where practical.
- Otherwise use lightweight IntersectionObserver-based state.
- Avoid heavy scroll event listeners.
- Respect `prefers-reduced-motion`.

## Implementation Boundaries

When implementing:

- Keep changes scoped to frontend files.
- Do not touch backend, Supabase, Netlify Functions, auth, credits, referrals, or AI pipeline unless explicitly requested.
- Use existing Tailwind/theme tokens where possible.
- Do not add new dependencies without asking.

## Review Output

When reporting results, include:

- Files changed
- Diff summary
- Desktop/mobile behavior
- Accessibility notes
- Remaining visual-review risks

## Reference Note

External skills such as OpenAI skills, Anthropic frontend-design, VoltAgent catalogs, and Tech Leads Club skills may be used as inspiration only after inspection. Do not bulk install third-party skill packs into Watheq.
